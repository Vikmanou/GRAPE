# Decisions, 2026-11-18

## 2026-11-18: Milestone 14 misses fixed, the owner's go-ahead

- **Search index budget**: `INDEX_BUDGET` in `crates/gfa-core/src/search/build.rs`
  goes from 1 GiB to 512 MiB. A 200k graph (about 200 M bases) no longer
  fits with every k-mer, so it keeps minimizers with window 3 and the exact
  match guaranteed to seed grows from 15 to 17 bases (k 15, window 3). Measured on the dev laptop: the sequence worker holds
  593 MB (was 1,080 MB) and the 200k tab with the index 962 MB (was 1,453 MB)
  against the 1,024 MB target. The 1M graph's index drops from 957 to
  731 MB.
- **Alternatives for the index**: a smaller `k` or a 2-bit bucket table would
  save less and change search results; a lazier index (built per query
  range) changes the worker protocol. A smaller budget is one constant.
- **GPU repulsion gets three far tiers**: the grid read exact pairs from the
  3x3 fine cells and the centroids of 5x5 coarse cells, and nothing beyond
  about 15 fine cells, so on a big component the far push of the rest of the
  graph was missing. It measured as 57.7k overlaps on the 1M graph against
  the CPU reference's 10.8k. Each tier is a hash of cells three times wider
  on a side than the one below (tier 1: 3 coarse cells, tier 2: 9, tier 3:
  27), read 5x5 around the node's own cell with the cells of the ring
  below taken out of their sums, the same way the coarse ring takes out the
  near cells. All three tiers share one table, salted by tier, and probing
  stops after 64 slots, so a table full of one-node components loses far
  cells instead of walking all of it. Cell indexes use integer floor
  division, not float, so a cell edge cannot flip on an inexact divide.
  `FAR_REACH`, `TAIL_REACH`, `TAIL_PER_COARSE` and `TAIL_TIERS` sit in both
  `level.ts` and the shaders; `web/tests/gpu/forces.ts` mirrors all of it in f64.
- **What was tried first, on the 1M graph** (overlaps GPU, CPU reference
  10,830; time to settle on the dev laptop, whose Intel gen 9 GPU is far
  slower than the owner's desktop):

  | Change                               | Overlaps | Settle |
  | ------------------------------------ | -------: | -----: |
  | none (control)                       |   57,727 |  179 s |
  | coarse reach 4 on every level        |   33,523 |  253 s |
  | reach 4 on levels up to 600k nodes   |   38,966 |  188 s |
  | every pair on levels up to 32k nodes |   39,260 |  282 s |
  | coarse reach 8 on every level        |   23,792 |  489 s |
  | one far tier, 3 cells                |   25,537 |  269 s |
  | two far tiers, 3 cells               |   15,909 |  380 s |
  | three far tiers, 3 cells             |   11,144 |  543 s |
  | three far tiers, 2 cells (kept)      |   12,830 |  404 s |

  Exact pairs on the coarse levels changed nothing, so the missing push
  mattered on the big levels, not the small ones. Reach alone costs about
  3.5 times per doubling; the tiers reach further for a fraction of that.

- **Result**: every graph in the standard set passes the tolerance, the 1M
  one with 12,830 overlaps against 10,830 (allowed 14,382) and edge CV 0.956
  against 0.851 (allowed 0.979); the 200k one with 1,053 against 1,110. The
  tiers push the layout wider, so edge CV and link stretch rise a little.
- **Cost and what is not shown**: the 1M layout takes about 2.3 times as long
  to settle as before on the dev laptop (421 s against 179 s; first usable
  80.6 s against 41.7 s). That laptop misses the time targets for 200k and
  1M both before and after (the targets were met on the owner's desktop at
  milestone 14: 6.9 s to settle at 1M), so the time targets are not
  re-checked here. For the owner's desktop to run: `npm run bench:layout`.
- **Not decided**: the small graphs' tab memory with the index reads "over
  300 MB" on the dev laptop because Chromium's own base is 100 MB larger
  there (289 against 190 MB before any index); the owner's desktop did not
  show that.
- **`compare_layout --gpu-only`**: measures a layout without computing the
  CPU reference, which takes 34 min at 1M, for trying changes quickly.
